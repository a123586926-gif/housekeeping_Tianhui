## 本輪決策與優先順序
1. **照片上傳暫停（已由使用者確認正式網站亦應暫停，但尚未授權執行正式部署）**：僅在 `feature/remember-login-30d` 分支，前端按鈕/檔案欄位停用，`POST /api/data/rooms` 於資料庫或 Storage 操作前拒絕；已上傳照片的 GET signed URL 仍維持原權限流程。**正式 main / 正式網站尚未停用**，需要正式環境的獨立切換授權與可測試部署。
2. **正式資料整理只讀**：保留原活動 ID、房間 ID、84 房配置、指派、人員排序；只建立結構對照與缺口清單，**不重寫、合併或刪除正式紀錄**。
3. **舊 PIN**：不讀取、不列印、不複製。正式啟用新登入前，逐人設新的強 PIN、伺服器儲存雜湊，並先在隔離環境演練；三筆空 PIN 不得默認通過。
4. **主檔 5 筆 vs 168 筆活動房間**：先確認 `rooms` 是否應成為正式固定主檔；如果不是，繼續使用活動房間獨立 ID，不自行補足 84 筆主檔。
5. **公開 Storage / anon CRUD**：屬正式權限風險；將新 API、身份與安全政策在隔離環境驗證後再一起切換。照片功能停用不代表既有 public bucket 已轉 private。
6. **正式切換門檻**：取得實際可回復的 DB/Storage 備份與還原驗證、遷移 dry-run、正式版本 QA E2E、回滾計畫、使用者明確核准。使用者已選擇先完成免費備份及還原驗證、再切換；**實際備份與隔離還原尚未執行，因此仍為 NO-GO**。
