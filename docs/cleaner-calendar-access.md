# 房務人員日曆權限（2026-11-03）

## 使用者需求
房務人員可以查看**所有活動的日曆排程內容**，不因沒有分配到房間而看不到該活動。
保留現有日曆視覺版型，日曆對房務人員為唯讀，沒有新增／修改／刪除活動的權限。

## 已完成的開發分支 API
- `GET /api/data/overview` 必須有有效伺服器工作階段。
- `calendarEvents` 提供所有活動的 `id`、`date`、`name`、`requiresCleaning`，供日曆顯示。
- 管理員的 `events`、`eventRooms` 仍以既有權限取得。
- 房務人員的 `events` 及 `eventRooms` 仍限於被指派的房間所屬活動，避免透過日曆取得住客／房號／房務檢查表。
- 日曆不提供 `notes`、`occupant`、`guest_name` 或房間明細；住宿人數不得從未授權的房間資料推算。
- 活動變更端點仍須驗證管理員權限。

## 待整合及驗收
- 此分支目前僅部署獨立 AuthSandbox 測試頁，`App.tsx` 仍為原版，尚未接到 `calendarEvents`。
- 獨立測試資料庫目前只有 `hk_auth_*` 表，尚無 `events` 與 `event_rooms`，所以新 API 的資料讀取仍待建立匿名假資料後進行測試。
- 整合時房務人員使用既有日曆元件，隱藏新增活動按鈕，點日期只顯示核准的日曆欄位；不得靠 CSS 隱藏保密資料，應只由 API 傳送允許內容。
- 驗收：兩位房務人員均看到所有日期活動，但只能看到／修改自己負責的房間，不能透過修改 API 新增或刪除活動。
- 未通過完整資料權限驗收前，不合併到 `main`。
