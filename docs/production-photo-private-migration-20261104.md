## 2. 安全的私人化流程（尚未在正式執行）

1. 正式 DB 與 Storage 檔案須先完成加密／限制存取的備份，並在隔離環境實際驗證可還原（檔案 hash、數量、內容一致）。
2. 保留現有 `cleaning-photos` 原封不動；不得先撤銷匿名策略或變更 `public` 屬性，以免舊網站中斷。
3. 正式另建**獨立的 private bucket**，以限定 MIME、大小及授權讀取設計。需驗證資料庫與 Storage 的權限及操作日誌。
4. 清查舊物件如何對應房間。**來源未關聯時一律待人工分類、不可做自動配對、不可刪除**。
5. 如經批准需保留舊照片，採 copy＋checksum 核對；複製到私有桶不等於已成功更新正式房間紀錄。資料庫引用必須在受控交易／可復原流程中處理。
6. 新版前端不提供 Storage 的公開 URL。以有權限的伺服器 API 取得 60 秒短效簽章 URL；管理員可查看授權房間，房務只可查看指派房間；未登入應 401、跨房間應 403。
7. 簽章 URL 在到期前可能仍能開啟；登出或撤銷帳號不會立即撤銷既有簽章 URL。敏感照片場景需視風險改用後端逐次授權的串流模式。
8. 在審核過的切換時段配合安全 API 正式部署，才關閉舊匿名讀寫及公開桶；保持完整回滾路徑和舊檔備份。**沒有用戶正式核准不得執行。**
